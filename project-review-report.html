严重问题（必须立即修复）
安全漏洞、数据丢失风险、功能完全不可用的缺陷
CRITICAL XSS 漏洞：About 页面直接渲染未净化的 HTML
About.tsx 使用 dangerouslySetInnerHTML={{ __html: about.aboutContent }} 直接渲染后端返回的 HTML 内容。后端 aboutService.js 没有任何 HTML 净化/转义逻辑。攻击者若通过管理后台注入恶意 <script> 标签，可窃取所有访问者的 admin_token 或执行任意操作。
修复方案：引入 dompurify 库，在渲染前净化 HTML：dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(about.aboutContent) }}。或在后端存储时进行净化。
src/pages/About.tsx:54
CRITICAL SSRF 漏洞：资源代理无域名白名单
vite.config.ts 中的 /res-proxy 和 /img-proxy 端点接受任意 URL 参数并代理请求。攻击者可利用此代理访问内网服务（如 http://localhost:3002/api/...、http://169.254.169.254/ 云元数据端点），造成服务器端请求伪造（SSRF）。
修复方案：添加域名白名单验证，只允许代理已知音乐/图片 CDN 域名。拒绝 localhost、127.0.0.1、169.254.x.x、10.x.x.x、172.16-31.x.x、192.168.x.x 等内网地址。
vite.config.ts:46-157
CRITICAL 默认管理员密码 "admin123" 硬编码
authService.js 中 getAdminPassword() 的最终 fallback 为 'admin123'。若部署时未设置 ADMIN_PASSWORD 环境变量且 auth.json 不存在，任何人都可以用 admin123 登录管理后台，执行文章/工具/语录的增删改。
修复方案：移除硬编码默认密码，首次启动时强制要求设置密码。或生成随机密码并打印到控制台。
server/authService.js:25
CRITICAL 密码明文存储在 JSON 文件中
authService.js 的 changePassword() 直接将新密码明文写入 server/data/auth.json。任何能读取服务器文件的人（或通过目录穿越漏洞）都能看到管理员密码。
修复方案：使用 bcrypt 或 crypto.scrypt 对密码进行哈希存储，永远不要存明文。比较密码时用 bcrypt.compare()。
server/authService.js:71
CRITICAL "瞬间/照片" 功能完全断裂 — 死代码
CommandPalette 引用 /moments 路由，Lightbox.tsx 组件存在，Photo 类型定义存在，fetchPhotos 在 store 中实现，后端 photoService.js 也有完整 CRUD — 但没有 Moments 页面组件，App.tsx 路由表中也没有 /moments 路由。用户点击命令面板的"瞬间"会跳转到 404 页面。
修复方案：创建 Moments.tsx 页面（照片墙 + Lightbox），在 App.tsx 注册路由 /moments。或移除 CommandPalette 中的引用。
src/components/search/CommandPalette.tsx:32, src/App.tsx (缺少路由)

高危问题（强烈建议修复）
影响安全性、性能、用户体验的重要问题
HIGH 无登录暴力破解保护
/api/auth/login 没有任何速率限制或登录尝试次数限制。攻击者可以无限次尝试密码，配合弱密码（如默认的 admin123），几秒内即可暴力破解。
修复：添加失败计数器，同一 IP 5 次失败后锁定 15 分钟。使用 express-rate-limit 或自行实现简单的 Map 计数器。
server/apiMiddleware.js:121-130
HIGH 无代码分割 — 首屏加载全部路由
App.tsx 同步导入了所有 20+ 个页面组件（Home、Thoughts、ThoughtDetail、Quotes、Treasure、Timeline、Music、About、NotFound + 11 个 Admin 页面）。用户访问首页时会下载管理后台的所有代码，严重影响首屏加载速度。Recharts（~200KB）等重依赖也被同步引入。
修复：使用 React.lazy() + <Suspense> 对路由进行懒加载，Admin 路由单独打包 chunk。
src/App.tsx:1-27
HIGH 无 Error Boundary — 组件崩溃白屏
整个应用没有 Error Boundary。任何组件的运行时错误（如 API 返回异常数据导致 .map is not a function）都会导致整个页面白屏，用户只能手动刷新。
修复：在 App.tsx 的 <Routes> 外层包裹全局 Error Boundary，在 <Layout> 内包裹页面级 Error Boundary。提供友好的错误恢复 UI。
src/App.tsx
HIGH Canvas 动画持续运行 — 移动端电池杀手
FluidBackground 和 MouseEffect 两个 Canvas 组件通过 requestAnimationFrame 持续运行渲染循环，即使页面不可见（切到后台标签页）也不停止。在移动设备上会严重消耗电池。同时 MouseEffect 的 z-50 层级覆盖在所有内容之上，虽然 pointer-events:none，但仍在每帧重绘。
修复：① 使用 document.visibilitychange 事件，页面不可见时暂停 rAF；② 添加 prefers-reduced-motion 检测，禁用动画；③ 在移动端关闭 MouseEffect（移动设备没有鼠标）。
src/components/effects/FluidBackground.tsx, src/components/effects/MouseEffect.tsx
HIGH Store 中所有错误被静默吞没
useStore.ts 中所有 catch 块都是 /* noop */。API 失败时，用户看不到任何错误提示，页面只是显示空白或加载中。例如 fetchArticles 失败后 articles 保持空数组，用户只看到"暂无文章"，无法区分"真的没文章"和"网络错误"。
修复：在 store 中添加 error 字段，catch 块中 set({ error: err.message })。在 UI 中显示 toast/错误提示。
src/store/useStore.ts (全文所有 catch 块)
HIGH CORS 配置为通配符 *
apiMiddleware.js 和 server/index.js 中 Access-Control-Allow-Origin: *。任何网站都可以调用你的 API，包括恶意网站。结合 Authorization 头，可能导致 CSRF 攻击。
修复：将 CORS 限制为实际部署域名，或至少在开发/生产环境区分配置。
server/apiMiddleware.js:84, server/index.js:44
HIGH 无 SEO 元数据 — 搜索引擎无法索引
index.html 只有 <title> 和基础 viewport。无 meta description、无 Open Graph 标签、无 Twitter Card、无 robots.txt、无 sitemap.xml。文章详情页不动态更新标题。SPA 的所有页面在搜索引擎看来都是同一个空白页。
修复：① 添加 react-helmet-async 动态管理 meta；② 创建 robots.txt 和 sitemap.xml；③ 添加 OG 标签用于社交分享。
index.html, 全项目
HIGH 无数据备份机制 — JSON 文件可能损坏
所有数据存储在 server/data/*.json 文件中。writeJSON 函数直接覆写文件。如果写入过程中服务器崩溃或断电，文件可能被截断为空或部分内容，导致所有数据永久丢失。多个并发写入也可能互相覆盖。
修复：① 写入时先写临时文件再原子重命名（writeFile → rename）；② 添加文件锁防止并发写入；③ 定期自动备份到 data/backup/ 目录。
server/dataService.js:32-41

中等问题（建议修复）
影响代码维护性、用户体验中等问题
MEDIUM 大量重复的 isDark ? ... : ... 三元表达式
几乎每个组件都有深度嵌套的 isDark ? 'dark-class' : 'light-class' 三元表达式。Tailwind 已配置 darkMode: 'class'，但完全未使用 dark: 前缀。这导致：① 代码量膨胀约 40%；② 阅读困难；③ 维护时需要同时改两处。例如 Header 组件一个 className 就有 6 层嵌套三元。
修复：全面改用 Tailwind dark: 变体，如 text-gray-900 dark:text-white。可移除 store 中的 isDark 字段，纯靠 CSS class 切换。
全项目几乎所有 .tsx 文件
MEDIUM 重复代码：formatDate / slugify / getIconColor 等多处重复
formatDate 在 ThoughtDetail.tsx 和 ArticleCard.tsx 中完全重复。slugify 在 ThoughtDetail.tsx 和 TableOfContents.tsx 中重复。getIconColor 和 ICON_COLORS 在 Treasure.tsx 和 ToolDetailModal.tsx 中重复。getLocalClicks 也在两处重复。
修复：提取到 lib/utils.ts 或单独的工具文件中，统一导入。
多处
MEDIUM 页面背景风格不一致
首页使用 FluidBackground 流体动画背景 + 友链区，视觉冲击力强。但其他页面（Quotes、Treasure、Timeline、Music、About）使用 bg-gray-950 / bg-gray-50 纯色背景，与首页风格完全脱节。用户从首页点进子页面时会感到明显的视觉断裂。
修复：统一设计语言 — 要么首页也用纯色+微妙渐变，要么子页面也加微妙的动态背景（如轻量版渐变光晕）。
MEDIUM 无页面切换动画
路由切换是瞬间的，没有任何过渡动画。用户在页面间导航时体验生硬，尤其是在从首页的沉浸式背景切换到子页面时。
修复：使用 framer-motion 的 AnimatePresence 或 CSS transition 添加页面进入/退出动画。
MEDIUM 音乐播放器缺少音量控制
Music.tsx 的底部播放条有播放/暂停/下一首按钮和进度条，但没有音量控制，也没有上一首按钮。用户无法调节音量，这是音频播放器的基本功能。
修复：添加音量滑块（audio.volume），添加上一首按钮，显示播放模式（顺序/随机/单曲循环）。
src/pages/Music.tsx:323-390
MEDIUM 无 Loading 骨架屏 — 加载体验差
所有加载状态都只显示"加载中..."文字。文章列表、语录、工具等页面在数据加载时显示空白 + 文字，视觉上像是出错了。没有骨架屏来保持布局稳定。
修复：为 ArticleCard、Quotes、Treasure 等卡片式列表添加骨架屏组件（带有 pulse 动画的占位卡片）。
MEDIUM articleService.js 单文件过大（30K+ tokens）
articleService.js 包含文章 CRUD + 种子数据生成，文件超大。种子数据直接内嵌在服务文件中，包含大量示例文章内容，难以维护。
修复：将种子数据提取到 server/data/seed-articles.json，将服务逻辑拆分。
server/articleService.js
MEDIUM 无测试 — 任何代码
项目中没有任何测试文件，没有测试框架配置。无论是前端组件还是后端 API，都没有单元测试、集成测试或 E2E 测试。重构时没有回归保障。
修复：至少为关键路径添加测试：① 后端 API 用 Vitest/Node test；② 前端关键组件用 React Testing Library；③ E2E 用 Playwright。
MEDIUM 无 ESLint 配置文件
package.json 有 "lint": "eslint ." 脚本，但项目根目录没有 .eslintrc 或 eslint.config.js 配置文件。ESLint 会使用默认配置，基本没有实际检查效果。
修复：添加 ESLint 配置（推荐 @typescript-eslint + eslint-plugin-react-hooks），配置 pre-commit hook（husky + lint-staged）。
MEDIUM 静态文件服务无缓存头
server/index.js 的 serveStatic 函数不设置 Cache-Control 头。每次请求都会重新读取文件，无法利用浏览器缓存。Vite 构建的文件名带 hash，可以安全地长期缓存。
修复：为 .js、.css、.woff2 等设置 Cache-Control: public, max-age=31536000, immutable，为 .html 设置 no-cache。
server/index.js:79-84
MEDIUM 后端 API 无输入验证
apiMiddleware.js 中所有 POST/PUT 端点直接将 readBody(req) 的结果传给服务层，没有验证必填字段、类型、长度。例如创建文章时可以提交空标题、超长内容、非法 category_id 等。友链提交没有 URL 格式验证。
修复：添加输入验证中间件，或使用 Zod/Yup schema 验证。至少验证必填字段、字符串长度、URL 格式。
server/apiMiddleware.js (全文)
MEDIUM 文章浏览量不增加 — getArticleById 不更新 views
articleService.js 的 getArticleById 只是读取文章数据返回，没有递增 views 字段。文章详情页虽然显示"X 次阅读"，但这个数字永远是 0（或种子数据的初始值）。
修复：在 getArticleById 中调用 writeJSON 更新 views + 1，或添加单独的 incrementViews 方法。
server/articleService.js:61-64

优化建议（锦上添花）
提升性能、可维护性、开发体验的建议
OPTIMIZE 未使用 prefers-reduced-motion
对动画敏感的用户（如前庭功能障碍患者）无法禁用 Canvas 动画和 CSS 过渡。OS 层面设置了"减少动态效果"但项目完全忽略。
在 CSS 中添加 @media (prefers-reduced-motion: reduce) 规则，在 JS 中检测并禁用 rAF 动画。
OPTIMIZE 无 PWA / Service Worker
无 manifest.json，无 Service Worker。移动端用户无法"添加到主屏幕"，无离线访问能力。个人博客网站特别适合 PWA 化。
使用 vite-plugin-pwa 添加 PWA 支持，自动生成 manifest 和 SW。
OPTIMIZE 无"返回顶部"按钮
文章列表、语录、工具箱等页面内容较长，用户滚动到底部后需要手动滑回顶部。虽然 html 有 scroll-behavior: smooth，但没有返回顶部按钮。
添加浮动"返回顶部"按钮，滚动超过 500px 时显示。
OPTIMIZE CommandPalette 未预加载文章/工具数据
命令面板搜索文章和工具时依赖 store 中已有的数据。如果用户直接打开命令面板（未先访问文章/工具页），搜索结果为空。
在命令面板打开时，如果 articles/tools 为空，自动 fetch。
src/components/search/CommandPalette.tsx
OPTIMIZE Header 和 Footer 重复请求站点设置
Header.tsx 和 Footer.tsx 各自在 useEffect 中调用 fetchSiteSettings()，导致同一数据被请求两次。
在 App.tsx 或 Layout.tsx 中统一调用一次，或添加 store 缓存判断 if (!siteSettings) fetch()。
OPTIMIZE 无 .env.example 环境变量文档
项目使用 process.env.ADMIN_PASSWORD 和 process.env.PORT，但没有 .env.example 文件。新开发者不知道需要配置哪些环境变量。
创建 .env.example 列出所有环境变量及说明。
OPTIMIZE 移动端导航菜单无动画
Header 的移动端下拉菜单用 {mobileOpen && ...} 条件渲染，出现/消失都是瞬间的，没有滑入/滑出动画。
使用 CSS transition 或 max-height 动画实现平滑展开。
src/components/layout/Header.tsx:152-204
OPTIMIZE 无 Dockerfile / CI-CD 配置
无 Dockerfile、无 GitHub Actions、无部署脚本。每次部署需要手动操作。
添加 Dockerfile + docker-compose.yml，配置 GitHub Actions CI（lint + build + deploy）。
OPTIMIZE 文章详情页 TOC 在移动端不可见
TableOfContents 使用 hidden lg:block，在移动端和平板（<1024px）完全不显示。长文章在移动端没有导航辅助。
移动端用底部浮动按钮展开 TOC，或用 <details> 折叠组件。
src/pages/ThoughtDetail.tsx:195
OPTIMIZE 无健康检查端点
后端服务器没有 /api/health 或 /healthz 端点。无法被 Docker/负载均衡器/监控工具探活。
添加 GET /api/health 返回 { status: "ok", uptime: ... }。
OPTIMIZE 无 .gitignore 检查 — 数据文件可能被提交
server/data/auth.json（含密码哈希）和用户数据文件可能被提交到 Git 仓库，造成数据泄露。
确保 .gitignore 包含 server/data/auth.json、server/data/*.json（保留示例数据）。
OPTIMIZE 主题切换无过渡动画
切换深色/浅色主题时，body 背景色瞬间变化，所有元素的颜色同时跳变，视觉上很突兀。
给所有颜色属性添加 transition-colors duration-300，或使用 View Transitions API。
OPTIMIZE 无 skip-to-content 链接 — 无障碍缺失
屏幕阅读器用户每次进入页面都需要从头导航 Header 中的所有链接。没有"跳到主要内容"的快捷链接。
在 Layout 最顶部添加 <a href="#main" class="sr-only focus:not-sr-only">跳到主要内容</a>。
OPTIMIZE Recharts 引入但未使用
package.json 依赖 recharts（~200KB gzip），但项目中没有任何图表组件使用它。Admin Dashboard 可能计划使用但未实现。
移除未使用的依赖，或在 Dashboard 中实现数据统计图表。
